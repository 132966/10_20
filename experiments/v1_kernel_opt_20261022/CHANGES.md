# 本次修改说明（2026-10-22）

这是独立的建索引算子优化实验，新增到 `experiments/v1_kernel_opt_20261022/`。此前的文档、共享精筛实验和原 SGLang 实现全部保留。本目录不表示已接入线上 SGLang。

## 保留的实现改动

|环节|此前|本次|实现|
|---|---|---|---|
|大组分组 N=1024/512/256/128|3次点积、2次锚点选择、1次排序|锚点选择融合进下一次点积，6次启动降到4次|`optimized.py` 的 anchored_dots|
|小组分组 N=64/32/16|同上|整轮融合为1次启动|`optimized.py` 的 split_fused|
|首轮1024成员排序|Triton 64位复合键排序|CUB 32位分数键＋成员值的稳定排序，同分保持原顺序|`sort_cub.cu`|
|页指纹|逐字节处理|32位加载后分解字节，成员独立归约，保留相同指纹|fingerprint_words|
|页查重|8448项字节比较|2112项32位比较＋64项成员比较，保留指纹碰撞复核|match_words|
|页发布|字节复制|32位复制，保留K与scale的位模式|publish_words|

7轮分组从42次 kernel 变为19次。大组融合使用独立的 PREV/OUT 工作区防止跨 program 竞争；增加两个 FP32[4096] 缓冲区，共32KiB。CUB 只用于首轮，较小组实测不划算。

## 未采用的实验

- Tensor Core：真实使用 TF32x3 MMA，但点积只有1～2个锚点，完整分组轮次更慢，近同分输入还可能改变排列，因此不默认启用。
- cuBLAS：动态成员打包＋bmm＋输出整理的开销超过收益，不采用。
- 64位 CUB 排序：没有收益，保留文件用于说明实验取舍。
- CUTLASS：未直接替换测试。查询打分已有 DeepGEMM Tensor Core 路径，本次未改查询后端。

## 实测与范围

H20，1K桶、单个Index K head、128维、每页64成员、4096页池。原实现与优化实现同卡交替测试。

|范围|模式|原实现 μs|优化后 μs|加速比|
|---|---|---:|---:|---:|
|初始化＋全部分组|eager|559.568|264.122|2.12×|
|初始化＋全部分组|CUDA Graph|89.330|55.012|1.62×|
|完整构建＋释放|eager|655.075|353.898|1.85×|
|完整构建＋释放|CUDA Graph|105.591|68.797|1.53×|

完整构建包含 initialize→分组→assemble→fingerprint→match→allocate→publish→release。release 为重复测试复原空闲池使用，不是生产纯构建耗时。编译、预热、捕获和CPU输入上传不计入；eager包含Python提交间隙。这不是查询、attention或完整推理加速比。

测试核对分组、页内容、中心、成员、指纹、页表与引用计数；覆盖复用/释放、碰撞、inactive，以及同一Graph更新源页表和桶起点。保留版本与参考版本逐位一致；尚未做完整模型精度回归。动态输入仍受预分配容量限制，跨流调度沿用原设计，本目录没有新增调度实现。
