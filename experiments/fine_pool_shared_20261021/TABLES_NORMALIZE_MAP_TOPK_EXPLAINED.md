# tables、normalize 和 map_topk：sink 与 tail 紧凑拼接的输入例子

这三个算子分别负责：**打分前准备输入 → 打分后整理分数 → 选完后找回原位置**。

本文按 **sink 和 tail 的有效数据紧凑拼接到临时缓存** 的目标布局讲解。本次更新的是设计说明，尚未同步修改或验证对应 kernel。

完整顺序是：

```text
准备固定候选缓存：将有效 sink 和 tail 的 K＋scale 紧凑复制
  ↓
tables
  ↓
精筛打分算子
  ↓
normalize
  ↓
TopK
  ↓
map_topk
  ↓
attention 读取选中的 K/V
```

下面用一个 Q 的例子说明：历史粗筛选中 **2 页，共 128 个候选槽位**，另有 **2 个 sink token 和 33 个 tail token**。每页存 64 个位置。以下编号均从 0 开始，按当前索引空间计数；需要位置展开时，按下游接口处理。

设 sink 的原逻辑位置为 `[0,2)`，tail 为 `[64010,64043)`，两段不重叠。这里 tail 的源起点并不页对齐，但复制时只取有效成员，不保留源页里的前置无效位置。

## 0. 先把 sink 和 tail 紧凑拼接

准备固定候选缓存时，将两段有效数据依次放入精筛池的临时区域：

```text
原生池中的有效位置：
  sink：[0,1]
  tail：[64010,64011,…,64042]
          ↓ 复制有效 K 及其 scale
临时固定候选页 C：
  [2 个 sink | 33 个 tail | 29 个末尾填充]
```

页 C 的槽位含义如下：

| 页内槽位 | 内容 | 对应原序列逻辑位置 |
|---|---|---|
| 0～1 | 2 个 sink | 0～1 |
| 2～34 | 33 个 tail | 64010～64042 |
| 35～63 | 29 个填充槽位 | 无有效候选 |

**sink 和 tail 之间没有填充，填充只在最后。** 源数据来自不同页，不影响把它们的有效成员复制到同一个目标页。

这一步需要实际复制数据，不能只改页表。每个 K 的 scale 也需要复制到目标槽位对应的 scale 区域，目标页仍沿用 K＋scale 的分页存储格式。

## 1. tables：告诉精筛去哪里读，以及读多长

固定候选页准备好后，`tables` 为这个 Q 生成精筛页表：

```text
[历史页 A，历史页 B，紧凑固定候选页 C]
```

`tables` 本身**只写页编号和长度，不复制 K**。

对应的打分布局为：

```text
历史页 A       历史页 B       固定候选页 C
64 个槽位      64 个槽位      2 个 sink＋33 个 tail＋29 个填充
```

因此：

| 输出或容量 | 本例 | 含义 |
|---|---:|---|
| 物理页总容量 | 192＝64＋64＋64 | 三个页面实际提供的槽位数量 |
| 打分长度 | 163＝128＋2＋33 | 从历史候选开始，到最后一个有效 tail 的布局跨度 |
| 紧凑候选长度 | 163＝128＋2＋33 | 供后续 TopK 使用的候选布局长度 |

最后一页只使用前 35 个槽位，长度参数在这里截断，末尾 29 个填充不进入有效打分范围。GPU 内部的计算块可能覆盖更大的范围，但不改变这个逻辑长度。

**本例的两个长度相等**，因为 sink 和 tail 已紧凑拼接，中间没有需要跳过的填充。历史槽位仍可能包含非法成员，所以长度 163 不一定意味着有 163 个合法候选。

如果固定候选超过 64 个，则继续紧凑写到后续临时页。例如 2 个 sink＋80 个 tail，占两页，第二页只有前 18 个槽位有效。仍只在固定候选区域末尾填充。

## 2. normalize：过滤非法分数，保持候选顺序

精筛输出的有效分数已经按下面的顺序排列：

```text
[128 个历史槽位分数 | 2 个 sink 分数 | 33 个 tail 分数]
```

对于本例，`normalize` **不再需要搬走 sink 后面的填充，也不需要跳过 tail 源页的前置无效位置**，因为复制阶段已经消除了这些空位。

它仍需检查候选合法性：

- 根据 `members` 恢复历史成员的原逻辑位置，排除未来位置和不属于本次有效历史范围的成员。
- 排除历史成员中与本次 sink/tail 固定范围重叠的成员，避免同一位置重复参加选择。
- 若分数缓冲区容量大于有效长度，将超出有效范围的部分屏蔽为 `-∞`，避免参与 TopK。

输出仍是：

```text
[128 个历史槽位分数 | 2 个 sink 分数 | 33 个 tail 分数]
        ↑
其中非法历史成员已置为 -∞
```

这里保留历史候选槽位，只将非法分数设为 `-∞`，不再把这些槽位压缩删除。因此 `map_topk` 仍可以按固定的区域边界解释候选编号。

**normalize 整理的是索引打分，不是 softmax，也不是归一化概率。** 紧凑拼接减少了本例的布局整理需求，不代表可以直接删除历史边界过滤。

## 3. map_topk：把候选编号还原为原序列逻辑位置

TopK 返回的是紧凑候选数组里的编号，不是原序列位置。

本例的候选编号分成三段：

| 候选编号 z | 区域 | 原序列逻辑位置的恢复方式 |
|---|---|---|
| 0～127 | 历史候选 | 通过候选页表和 `members` 查找 |
| 128～129 | sink | `z－128` |
| 130～162 | tail | `64010＋(z－130)` |

### 历史候选例子

假设 TopK 选中候选编号 70：

```text
候选 70
  ↓ 70 // 64 = 1，70 % 64 = 6
第二个历史候选页，页内偏移 6
  ↓ 通过候选页表定位该页，再读取 members
原序列逻辑位置：4200
  ↓ 4200 // 64 = 65，4200 % 64 = 40
原序列逻辑页：65，页内偏移：40
```

`4200` 是说明成员映射关系的假设值。

### 拼接后的 tail 例子

假设 TopK 选中候选编号 132：

```text
候选 132
  ↓ 位于固定候选区域，区域内偏移 132－128＝4
临时页 C 的槽位 4
  ↓ 前两个槽位是 sink，因此 tail 内偏移为 4－2＝2
原序列逻辑位置：64010＋2＝64012
  ↓ 64012 // 64 = 1000，64012 % 64 = 12
原序列逻辑页：1000，页内偏移：12
```

**临时页 C 的槽位 4，不是原序列的第 4 个位置。** 拼接后的地址只用于精筛，恢复原位置需要知道 sink 长度和 tail 起点。

这里说明到原序列的逻辑页及页内偏移即可。（读取 K/V 时再通过当前请求的页表定位原生物理页；若接口要求，也可继续转换为原生物理 slot。）

## 4. 同一个 chunk 的多个 Q 如何共享

上面的 163 是单个 Q 的紧凑布局例子。多个 Q 要共享缓存，必须明确它们共享的固定范围，不能把每个 Q 的私有紧凑副本称作公共缓存。

例如，多个 Q 的 sink 都是 `[0,2)`，tail 起点都为 64010，只有因果可见终点不同。可以复制一次最长的 tail，再让各 Q 使用自己的长度：

```text
公共固定候选缓存：
[2 个 sink | 从 64010 开始的公共 tail | 末尾填充]

Q0：tail 可见 33 个 → 固定候选有效长度 35
Q1：tail 可见 34 个 → 固定候选有效长度 36
```

这时各 Q 引用相同缓存，长度参数分别截断可见前缀。

若各 Q 的 tail 起点也不同，则不能仅靠一个末尾长度裁剪来排除多余的前置成员。需要公共范围的布局描述和逐 Q 的有效区间，由过滤与映射处理这些差异；这类情况下，打分跨度和紧凑候选长度不一定相等。sink 与 tail 重叠时也应先按逻辑位置取并集，保证每个固定候选只复制一次。

## 三者的区别

| 算子或准备步骤 | 最直接的作用 |
|---|---|
| 固定候选紧凑复制 | **把有效 sink＋tail 的 K 和 scale 拼到临时页中** |
| `tables` | **安排去哪些页打分，设置实际长度** |
| `normalize` | **过滤非法及重复覆盖的候选；本例无需移除中间填充** |
| `map_topk` | **找回原序列逻辑页及页内偏移**（按接口需要继续转换为物理 slot） |

实施这种布局需要一起调整固定候选复制、`tables`、`normalize` 和 `map_topk`，并核对精筛后端的长度与页表接口。本次仅更新文档，未改 kernel，也未测量性能；上述顺序不表示已经融合成一个 kernel。
