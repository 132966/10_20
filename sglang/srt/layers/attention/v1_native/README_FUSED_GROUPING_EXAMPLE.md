# fused_grouping.py：数据例子与真实 kernel 测试

## 先区分 4K 包装接口与当前 1K 调用

同目录 `fused_grouping.py` 中的 `FusedGroups.run()` 固定处理 **4096 个 K**，维度固定为 128；最终分成 512 组，每组 8 个成员。它只返回成员排列，不生成重排 K、中心、物理页或成员映射。

当前 V1 的 1K 建索引没有调用这个 4K 包装接口，而是由 `../v1_deepseek/runtime.py` 的 `Build.compute()` 直接调用 `_dots`、`_anchor`、`_sort`，最终得到 128 组。不要直接给 `FusedGroups.run()` 输入 1024 个 K。

## 运行例子

```bash
# 在本 README 所在目录运行；纯 Python 数据演示，不需要 GPU。
python example_fused_grouping.py

# 在已经安装 torch、triton 的原测试环境运行真实 4K GPU 测试。
python example_fused_grouping.py --gpu --device cuda:0
```

脚本只分配小型测试张量，不加载模型、不启动服务、不改原实现。GPU 测试明确设置 fused 模式；默认环境下原包装接口可能走 reference 路径，不能据此验证这些 Triton kernel。

## 8 个成员手算演示

这里只用 8 个成员讲算法，并演示拆成 4 个两成员小组，不是改变真实 kernel 的固定尺寸。假设归一化后向量仅第 0 维非零：

```text
成员编号：0  1  2  3  4  5  6  7
向量方向：+1 -1 +1 -1 +1 -1 +1 -1
初始 P：[0,1,2,3,4,5,6,7]
```

|步骤|本例结果|实现|
|---|---|---|
|选择初始参考|s=0|`_dots` MODE=0 读取组内第一个成员|
|计算与 s 的点积|[1,-1,1,-1,1,-1,1,-1]|`_dots` MODE=0|
|选择 b|b=1；最小值同分时取当前排列最左侧|`_anchor` SLOT=0|
|计算与 b 的点积|[-1,1,-1,1,-1,1,-1,1]|`_dots` MODE=1|
|选择 a|a=0|`_anchor` SLOT=1|
|计算相似度差|[2,-2,2,-2,2,-2,2,-2]|`_dots` MODE=2：dot(K,a)-dot(K,b)|
|稳定降序排列|[0,2,4,6,1,3,5,7]|`_sort`|
|拆成两半|[0,2,4,6] 与 [1,3,5,7]|下一轮按更小 N 解释排列|

下一轮每个组内部方向完全相同，两个锚点可能是同一成员，分差全为 0。稳定排序保持当前顺序，再平均拆成 `[0,2]、[4,6]、[1,3]、[5,7]`。这说明分组保证平衡，不要求锚点必须不同。

两轮读写分别为 `perm[0] → perm[1]`、`perm[1] → perm[0]`；交换的是数组角色，没有复制 K。

## 真实 4K GPU 测试的输入输出

|输入|shape|构造|
|---|---|---|
|k|[4160,1,128]，BF16|只有第 0 维非零，方向正负交替，幅值 1～7|
|slots|[4160]，int32|固定随机种子的物理 slot 排列|
|start|Python 整数|64，即处理逻辑位置 64～4159|
|flag|标量 int32|-1 表示执行|

第 i 个桶内成员从 `k[slots[64+i],0,:]` 读取。物理 slot 被打乱，但输出仍应是原序列逻辑位置，不是物理 slot。

`_init` 把每个 K 归一化，并将 `P` 初始化为 `[64,65,…,4159]`。随后按 N=4096、2048、1024、512、256、128、64、32、16 逐级分组。

输出 shape 为 `[1,4096]`，可解释为 `[1,512,8]`。本例的预期排列可精确写出：

```text
先是正方向：64,66,68,…,4158
然后负方向：65,67,69,…,4159
第一个组：[64,66,68,70,72,74,76,78]
第一个负方向组：[65,67,69,71,73,75,77,79]
```

脚本检查：所有成员恰好出现一次、同方向分组正确、同分稳定排序正确、原始 K 未修改，以及 flag=0 时排列缓冲区保持哨兵值不变。使用只有一维非零的输入，是为了避开浮点归约差异，使预期排列明确；这不代替随机数据、真实模型精度或性能测试。

## 与当前 1K 建索引的衔接

1K 路径使用自己的 `initialize` 读取分页 FP8 K；复用本文件三个分组 kernel，N 从 1024 开始。分组完成后，另一个文件里的 `assemble` 才生成 16 个重排页和 128 个中心。

本文件底层 kernel 含固定 4096/head 等步长。当前 1K 路径以单 head 调用，使 head 索引为 0；不能直接把紧凑 1K 缓冲区改成多 head 网格调用。
