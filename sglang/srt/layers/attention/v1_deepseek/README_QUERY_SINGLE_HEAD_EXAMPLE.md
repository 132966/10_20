# 单头 v1_query.cuh 小型真实算子测试

脚本：`example_v1_query_single_head.py`。调用生产代码的 `query_fused.module()`，实际执行 `v1_query.cuh` 的 route 和 topk；不修改原算子。

## 数据规模

- 一个 KV head、一个 Q head、维度 128。
- K 有 4097 个位置，前 4096 个模拟已建立的四个 1K 桶。
- Q 有 1024 行；不是 1024 个 head。当前原始融合 TopK 接口强制要求 B>512，不能直接传一行。
- 为使例子容易核对，所有 Q 都相同、可见长度都为 4097；这模拟多个相同查询，**不是一个因果 prefill chunk 的逐行长度设置**。
- 重排页和原生页分别随机映射到物理页；每个 1K 桶内成员倒序，模拟已有的成员排列，不在本测试里重新聚类。
- K 仅第 0 维非零，K[i,0]=i/8192；Q 第 0 维为 1。实际执行矩阵乘法，因此分数可直接核对且没有同分歧义。

## 真实调用与参考检查

1. 每组 8 个 K 求中心，计算 Q 对中心的点积。
2. `route` 对每页 8 个中心取 max，选 40 个重排页，并直接写精筛物理页表。用 PyTorch max/topk/gather 逐项核对。
3. 根据所选页读取成员，形成 2560 个重排候选；再加 64 个 sink 位置与 64 个尾部位置，共 2688 个精筛候选。
4. 计算真正的 Q·K 精筛分数。将 scores 传给 `topk`，在融合 kernel 中过滤重复边界位置，再选 Top2048，并同时输出逻辑位置、原生物理 slot。
5. 用独立 PyTorch mask/topk 结果核对选中集合，逐项验证 raw→logical→physical 的映射，检查无重复。
6. 分别测试 direct_fine=False 和 True：从请求重排页表间接映射，以及直接从精筛页表映射。

本例预期首先选中的页面逻辑编号是 `[48,49,50,51,52,53,54,55,...]`，因为桶内倒序排列导致最后一个桶的第一页分数最高。对应物理页是随机页表中的编号，不能直接把选页编号当物理页。

## 范围

这是真实 CUDA 融合算子的正确性示例，输入是人工构造的数据，不是模型采集数据。打分参考使用 PyTorch FP32 矩阵乘法，没有调用 DeepGEMM FP8 打分，也没有运行最终 attention、CUDA Graph 或性能基准。当前单头示例不做 ×4 输出展开。

在原有 SGLang 环境、并将此仓库根目录加入 PYTHONPATH 后运行：

```bash
python example_v1_query_single_head.py
```

## 实测结果

已在原 CUDA 环境运行通过：1024 个 Q、单头，Q=[1024,128]、K=[4097,128]、精筛分数=[1024,2688]、输出=[1024,2048]。页面 max/TopK/页表写入，以及 direct_fine=False/True 两条 Top2048、过滤和位置映射路径均与参考结果一致。

空展开张量按生产代码使用 empty_strided((B,0),(0,1))，以满足接口的布局检查。
